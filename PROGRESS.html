The loop (why the order is test → code → gate → commit)

DeepSeek writes the failing check before any implementation and records the RED, so a test can never be reverse-fitted to whatever got built. The orchestrator re-runs the gate itself — an executor's PASS is a claim until proven — commits one feature per commit, and deletes the debt entry in the same commit that fixes it.
