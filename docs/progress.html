Security, in the order it was built

  1. Sign-in foundation. scrypt password hashing, HttpOnly + SameSite=Strict session cookies, an X-Requested-With header required on every write, and a strict Content-Security-Policy with no inline script or style.
  2. Least privilege. Role lists per object type with superadmin always allowed, and machine tokens scoped to named points and actions.
  3. Brute force and audit. Five failed logins lock a name. Failed sign-ins and lockouts of real accounts are audited; made-up names are not, so an outsider cannot fill the audit trail.
  4. Outbound trust. MQTT verifies the broker certificate and hostname, webhooks do not follow redirects, and SMTP passwords live in a credential file rather than the config.
  5. Session lifecycle. The console signs itself out after 30 minutes without input, sessions end after 8 hours regardless, and a password reset or account disable signs the person out everywhere at once.
  6. A second factor. TOTP with single-use codes; losing the phone needs a live administrator, not an email link.
  7. Secure transport. TLS 1.2 or newer, HSTS, and a Secure cookie flag. Without a certificate the server refuses to listen on any address other than localhost, so a password is never put on the network in clear.
