Security, in the order it was built

  1. Sign-in foundation. scrypt password hashing, HttpOnly + SameSite=Strict session cookies, an X-Requested-With header required on every write, and a strict Content-Security-Policy with no inline script or style.
  2. Least privilege. Role lists per object type with superadmin always allowed, and machine tokens scoped to named points and actions.
  3. Brute force and audit. Five failed logins lock a name. Failed sign-ins and lockouts of real accounts are audited; made-up names are not, so an outsider cannot fill the audit trail.
  4. Outbound trust. MQTT verifies the broker certificate and hostname, webhooks do not follow redirects, and SMTP passwords live in a credential file rather than the config.
  5. Session lifecycle. The console signs itself out after 30 minutes without input, sessions end after 8 hours regardless, and a password reset or account disable signs the person out everywhere at once.
  6. A second factor. TOTP with single-use codes; losing the phone needs a live administrator, not an email link.
  7. Secure transport. TLS 1.2 or newer, HSTS, and a Secure cookie flag. Without a certificate the server refuses to listen on any address other than localhost, so a password is never put on the network in clear.

Open now

The 2026-10-28 AI/ML work was verified on synthetic series only. All eleven findings of the 2026-10-27 audit (docs/12-error-handling.md, NEXTPLAN.md section 1) are closed, each with a test. What is open now is in TECHNICAL_DEBT.md, and every entry is a path that has only met a simulator or a fake server.

  1. Modbus, email/Slack/escalation delivery, SNMP, Sparkplug B, DNP3, BACnet/IP and OPC UA (U1, U3, U8 to U12) have never met real hardware or a real external server.
  2. eGauge, Haystack and POP3 (U13) were run against fake servers only. POP3 STARTTLS and SSL and Haystack authentication beyond a Bearer token are untested.
  3. LDAP sign-in (U14) ran against a fake directory on plain ldap:// localhost; ldaps:// never ran, and result codes 51 and 52 count as a bad password.
  4. The SQL console MySQL/MariaDB branch has not been run; the SQLite branch is tested. The console byte caps, the performance_schema/sys secret additions, the atomic migration v11 and the partial-backup cleanup have not run on MySQL/MariaDB either.
  5. Seven entries (W1 to W7) were left by the 10-28 work: POP3 now defaults to ssl and refuses patterns with three or more open-ended repeats, so common ones such as Temp:\s*(...) must be rewritten; TREND_LIMIT state is memory-only and UNCERTAIN values enter its fit; the robust forecast band is constant width; model retraining is once a day and the stored profile serves only the 14-day window; LDAP login timing is untested; dashboards accept unknown keys.
